🎓 Exemplo Didático — Cálculo Proporcional de Área

Quando um alerta MAPBIOMAS sobrepõe parcialmente uma Autorização Vigente (ASV), a área não é classificada inteiramente como legal ou ilegal. O gpd.overlay(how='intersection') calcula a sobreposição real:

❌ Método Antigo (Binário)

Critério: alerta toca a ASV?

Sim → 100 ha = 100% LEGAL

Não → 100 ha = 100% ILEGAL

Resultado: 0 ha ilegal (ERRADO)

✔ Método Corrigido (Overlay)

gpd.overlay(alertas, asvs, how='intersection')

Interseção real: 34,6 ha (legal)

Resíduo: 100 − 34,6 = 65,4 ha (ilegal)

IPI = 65,4 / 100 × 100 = 65,4%

Etapa Operação Área Resultado
1Alerta MAPBIOMAS100,0 haBase do cálculo
2Autorização (ASV)80,0 haLimitador geométrico
3Intersecção (overlay)34,6 ha✔ LEGAL
4Diferença65,4 ha✘ ILEGAL
5IPI = 65,4/100×100—65,4%

📐 Premissas Metodológicas (v2.1)

✔ P1 — Intersecção proporcional por gpd.overlay(how='intersection')
✔ P2 — Vigência temporal verificada: dt_valid_i ≤ dt_deteccao ≤ dt_valid_f
✔ P3 — Projeção EPSG:5880 (SIRGAS 2000 / Brazil Polyconic) — cobre fusos 23S e 24S
✔ P4 — Buffer 50m + make_valid() pós-buffer
✔ P5 — H3 via geo_to_cells (cobertura poligonal, não centroide)
⚠ Este dashboard usa IPI como proxy bruto (sem intersecção espacial). A classificação real legal/ilegal requer execução do pipeline Python/GeoPandas descrito na documentação v2.1.
⚠ DERADSAs 2022–2023 ausentes. Alertas desse subperíodo confrontados apenas com ASVs → falso positivo potencial ±15%.

📋 Relatório de inconsistências detectadas na varredura do projeto (v2.1 vs dados reais). Resultado: 5 críticas · 3 altas · 2 médias · 1 baixas

Inconsistências Detectadas — Documentação v2.1 vs Dados Reais

SeveridadeCampo / ArquivoDescrição
CRÍTICA CODEALERTA vs id_alerta Doc usa id_alerta — dado real usa CODEALERTA. Dashboard usa CODEALERTA.
CRÍTICA DATADETEC vs dt_deteccao Doc usa dt_deteccao — dado real usa DATADETEC (ISO YYYY-MM-DD).
CRÍTICA AREAHA vs area_ha Doc usa area_ha — dado real usa AREAHA. Pipeline deve mapear campo correto.
CRÍTICA VPRESSAO vs status Doc esperava campo status (Confirmado/Em análise). Dado real tem VPRESSAO (vetor: agriculture, etc.). Sem campo de status de confirmação no dado.
CRÍTICA dt_valid_i/dt_valid_f (serial Excel) Datas nas ASVs estão em número serial Excel (ex: 46064.125), não ISO. Conversão obrigatória: (serial-25569)*86400*1000 ms.
ALTA Alertas de desmatamento-pi.xlsx (nome errado) Arquivo nomeado como alertas contém dados de ASVs (27 colunas SINAFLOR+). Arquivo de alertas tabulares não existe em xlsx — usar GeoJSON.
ALTA DERADSAs sem coluna Município no XLSX XLSX 2024 e 2025 não possuem coluna Município (somente Id, Área/ha, Houve Auteração, Ano). Município deve ser derivado do GeoJSON via sjoin.
ALTA FONTE em formato {DETER-CERRADO} Campo FONTE dos alertas usa sintaxe de array PostgreSQL ({DETER-CERRADO,GLAD}) — não string simples como 'Sentinel-2'. Representa sistemas de detecção múltiplos.
MÉDIA CRS EPSG:4674 vs EPSG:4326 Documentação cita EPSG:4326 (WGS84). Dado real está em EPSG:4674 (SIRGAS 2000). Praticamente equivalentes no Brasil, mas código EPSG deve ser corrigido no pipeline.
MÉDIA Houve 'Auteração' (ortografia) Campo nos XLSX de DERADSAs tem erro ortográfico: 'Houve Auteração' em vez de 'Houve Alteração'. Normalizar no pipeline.
BAIXA DERADSAs GeoJSON: apenas Id e Ano GeoJSONs de DERADSAs possuem somente Id e Ano — sem área, sem município. Área deve ser obtida dos XLSX via merge por Id.
